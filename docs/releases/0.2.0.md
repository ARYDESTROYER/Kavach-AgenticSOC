# Agentic SOC 0.2.0

Agentic SOC **0.2.0** opens documentation line **0.2**. It is a **Testing candidate**.
It is not tagged and it is not an installable Stable release yet. The frozen release
preparation writes the full release notes on this page before the tag.

Version 0.2.0 carries everything built on `Testing` since 0.1.12. It also folds in
the 0.1.13 candidate, which was never tagged: the legacy bootstrap correction that
treats a missing state-schema label the same way on both installed components. See
[Agentic SOC 0.1.13](0.1.13.md).

!!! warning "A candidate is not an installable Stable release"

    Branch content, a version string, an image tag or a signature alone is not
    update authority. Version 0.2.0 is installable only after the exact accepted
    `main` commit has the immutable annotated tag `v0.2.0`, the tag and release
    workflows pass, all three public pinned images and signatures verify, the
    canonical plan and bundle publish, and canonical v0.1.1 supervised-update plus
    browser acceptance succeeds. Never move or reuse the tag.

## Before you upgrade: set the update repository

The repository is now `ARYDESTROYER/Kavach-AgenticSOC`. That name is the update
trust root. It names the signing identity of every release plan, the GHCR image
namespace, the OCI source label, the release discovery default and the public
documentation address.

Add this line to `.env` on the deployment host before you run the bootstrap:

```text
AGENTIC_SOC_UPDATE_REPOSITORY=ARYDESTROYER/Kavach-AgenticSOC
```

The bootstrap script refuses to run when the line is missing, when it still names
`ARYDESTROYER/Agentic-Kibana` in any letter case, or when it names the new
repository in the wrong letter case. The signing identity is case-sensitive. The
script prints the exact line to add and never edits `.env` itself.

What else changes with the name:

- The publisher identity, the GHCR namespace and the OCI source label all use the
  new name.
- Artifacts of v0.1.12 and earlier stay valid under the former identity. They are
  not re-signed.
- GitHub does not redirect project Pages after a rename. Old
  `arydestroyer.github.io/Agentic-Kibana/` links answer 404. The public Stable
  Help Center is now `https://arydestroyer.github.io/Kavach-AgenticSOC/stable/`.
- A saved **Updates & releases** preference that names the former repository, in any
  letter case and with or without `.git`, now reads as the new repository. A fork
  or any other repository you saved is kept.

## Signed plan and compatibility

Plan schema remains **1**, updater protocol remains **1** and state schema remains
**1**. The release record must bind:

- product `agentic-soc`, version `0.2.0`, tag `v0.2.0`, channel `stable`, and the
  exact 40-character lowercase tag commit;
- supported source versions `>=0.1.1,<0.3.0`, so the v0.1.1 baseline is admitted
  and a later 0.2 patch can follow;
- PostgreSQL-owned state only, a verified backup and migration strategy `none`;
- the exact frozen Compose SHA-256
  `e3f7ecbb0f749cc9d88f4392c58c9a63ddbd064e80ecde9f21fe9de199086fd4`;
- the three immutable component references and matching OCI labels.

`deploy/docker-compose.agnostic.yml` stays byte-identical. It still defaults the
update repository to the former name, which is why the bootstrap requires the
`.env` line above.

## Exact Stable build identity

Build the accepted tag with explicit immutable metadata:

```bash
export TLSOC_VERSION=0.2.0
export TLSOC_RELEASE_CHANNEL=stable
export TLSOC_BUILD_SHA="$(git rev-parse 'v0.2.0^{}')"
export TLSOC_BUILD_DATE="$(git show -s --format=%cI 'v0.2.0^{}')"
```

The backend build-info endpoint, Web `/release.json`, plan, image labels and tag
must agree on that version, channel and commit.

## Immutable annotated-tag checklist

1. Merge the exact candidate through protected `Testing` after its fail-closed
   `CI passed` aggregate succeeds.
2. Verify the resulting Testing push aggregate, then promote the content to
   protected `main` through a pull request without release-content drift.
3. Verify the exact `main` push aggregate.
4. Create the annotated tag once from that accepted main commit:

   ```bash
   git tag -a v0.2.0 -m "Agentic SOC v0.2.0"
   git show --no-patch --format=fuller v0.2.0
   git push origin refs/tags/v0.2.0
   ```

5. Require exact-tag CI and the signed-release workflow to pass completely. Do not
   use `continue-on-error`, move the tag, or republish altered artifacts.
6. Verify public assets, anonymous digest reads, keyless signatures, canonical
   bootstrap, supervisor receipt, application health and browser controls before
   declaring the release installable.

### First publication under the new name: make the packages Public

The first push to the new GHCR namespace creates three private packages. The release
workflow's step "Prove anonymous pullability and exact OCI release labels" then stops
before any plan, attestation or Release exists. This is a designed pause, not a
burnt tag. To continue:

1. Set each of these packages to **Public** (this cannot be undone):
   `ghcr.io/arydestroyer/kavach-agenticsoc/backend`,
   `ghcr.io/arydestroyer/kavach-agenticsoc/webui` and
   `ghcr.io/arydestroyer/kavach-agenticsoc/updater`.
2. Under each package's **Actions access**, confirm the repository has write access.
3. Re-run the failed release workflow.
4. The Documentation workflow waits at most 2 hours for the signed release. If that
   wait expired, run the Documentation workflow by `workflow_dispatch` on the
   `v0.2.0` tag.

## Operator bootstrap

Use a clean checkout of the accepted tag on the host that owns the canonical
deployment, with `AGENTIC_SOC_UPDATE_REPOSITORY=ARYDESTROYER/Kavach-AgenticSOC`
already in `.env`:

```bash
git clone --branch v0.2.0 --depth 1 \
  https://github.com/ARYDESTROYER/Kavach-AgenticSOC.git agentic-soc-0.2.0
cd agentic-soc-0.2.0
test "$(shasum -a 256 deploy/docker-compose.agnostic.yml | awk '{print $1}')" = \
  "$(tr -d '[:space:]' < deploy/update-base-v1.sha256)"
test "$(git cat-file -t v0.2.0)" = "tag"
test "$(git describe --tags --exact-match)" = "v0.2.0"
test "$(git rev-parse HEAD)" = "$(git rev-parse 'v0.2.0^{}')"
test -z "$(git status --porcelain --untracked-files=all)"
./scripts/bootstrap-updater.sh
```

The Console must then report `v0.2.0 · Stable`, and its release manifest and the
healthy backend must agree on the exact commit.
