# Agentic SOC 0.2

Agentic SOC 0.2 is the second documentation and application release line.
Human-facing documentation uses **0.2**; the current source version is Semantic
Version **0.2.0**. Under the project's own rules a new pre-1.0 capability set is a
MINOR release, so the work built on `Testing` after 0.1.12 ships as 0.2.0 and not
as another 0.1 patch. The 0.1.13 candidate was never tagged; its legacy bootstrap
correction is folded into 0.2.0.

Builds on `Testing` are integration and acceptance builds. Version 0.2.0 is a
supported Stable release only when the accepted tree is on `main`, the resulting
commit has passed the release gate, and that exact commit is tagged `v0.2.0` with
verifiable signed release artifacts and public image digests. Until then, the last
verified installable Stable release is v0.1.1. Branch state alone never establishes
the installed release identity.

## What changes with the 0.2 line

- **Repository identity.** The repository is `ARYDESTROYER/Kavach-AgenticSOC`. It is
  the update trust root, the GHCR namespace, the OCI source label, the release
  discovery default and the public documentation address. Set
  `AGENTIC_SOC_UPDATE_REPOSITORY=ARYDESTROYER/Kavach-AgenticSOC` in `.env` before
  you bootstrap; the bootstrap refuses to run without it.
- **License.** The project is licensed under Apache-2.0.
- **Help Center.** The installed guide is served under `/docs/0.2/`. Addresses under
  `/docs/0.1/` redirect to the same page of the 0.2 line, keeping any `#` part.
- **Plan range.** Release plans admit source versions `>=0.1.1,<0.3.0`, so a 0.2
  install can accept the next 0.2 patch.

The updater protocol, the signed plan schema, the application state schema and the
frozen Compose base do not change.

## Upgrade and support boundary

Back up the state store and deployment secrets before changing versions. Read the
detailed [0.2.0 release record](0.2.0.md) before promoting or upgrading, and the
[Upgrade operations](../operations/upgrades.md) guide for the bootstrap steps.

The 0.1 line stays as history. See [Agentic SOC 0.1](0.1.md) for its releases and
publication records, [Documentation versions](documentation-versions.md) for the
address rules, and [Known limitations](known-limitations.md) before shared use.
