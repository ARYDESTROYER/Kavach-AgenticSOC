# Agentic SOC 0.1.13

Agentic SOC **0.1.13** was a candidate in the **0.1** documentation line. It was
never tagged and never published: no immutable `v0.1.13` tag, GitHub Release, signed
upgrade plan or Stable image set exists. Its content is folded into
[Agentic SOC 0.2.0](0.2.0.md). It remains here only as a historical record.

!!! danger "Unpublished candidate, folded into 0.2.0. Do not deploy or tag."

    There is no official `v0.1.13` release artifact, update plan or bootstrap
    target. Do not create that tag retroactively and do not run release or bootstrap
    commands copied from earlier drafts of this page. Use the
    [0.2.0 release record](0.2.0.md) and the current
    [upgrade guide](../operations/upgrades.md).

## What the candidate corrected

The candidate corrected the canonical-runtime blocker found after the otherwise
complete v0.1.12 signed publication. The immutable v0.1.12 images, plan, bundle,
signatures, attestations, anonymous pulls, GitHub Release and Stable documentation
all verified. Its canonical v0.1.1 bootstrap then stopped safely before application
mutation because both legacy application images omit the state-schema OCI label and
the updater compared one normalized missing value with one raw missing value.

The correction normalizes an absent state-schema label on both installed components
to the same explicit `unknown` value for coherence comparison. The existing one-time
v0.1.1 bootstrap exception may then evaluate that coherent legacy identity. Mixed
labels still fail. Every later release still requires matching version, channel,
immutable revision, image IDs and state-schema-1 labels.

- Canonical v0.1.1 deployments whose backend and Web images both omit
  `io.agentic-soc.state.schema` can pass the intended one-time host-authorized
  bootstrap identity check.
- A deployment where just one component has the label remains blocked as a mixed
  identity.
- Version 0.1.2 or later without exact managed Stable identity and schema-1 labels
  remains blocked. The fix does not create a general source-build escape hatch.

## Why this is not Stable

SemVer and channel provenance are separate. A package or source tree could report
`0.1.13` while remaining Testing. Stable identity additionally requires the exact
accepted `main` commit, an immutable annotated tag with matching version, successful
fail-closed CI on Testing, `main` and that tag, public digest-pinned images signed by
the tagged release workflow identity, a signed canonical upgrade plan and Sigstore
bundle, and an immutable GitHub Release with the verified asset inventory. None of
those exists for 0.1.13.

The work built on `Testing` after this candidate is a new capability set, which the
project's versioning rules make a MINOR release. It therefore ships as 0.2.0 in
documentation line 0.2, under the repository identity `ARYDESTROYER/Kavach-AgenticSOC`.
Drafts of this page named the former repository `ARYDESTROYER/Agentic-Kibana`; that
identity remains valid only for artifacts of v0.1.12 and earlier.

For current compatibility, rollback limits, exact artifacts, verification commands
and the immutable-tag procedure, use [Agentic SOC 0.2.0](0.2.0.md),
[Known limitations](known-limitations.md) and
[Release channels and versioning](channels.md).
